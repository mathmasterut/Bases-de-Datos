Tema 1: Manual de Simbología (Diagramas E-R)

¿Qué es un Diagrama E-R? Es una herramienta gráfica que se utiliza para modelar el diseño lógico de una base de datos. Permite visualizar de forma clara cómo se estructuran los datos y cómo interactúan entre sí. A continuación, se detalla la simbología estándar (modelo de Peter Chen) que debes dominar.

1. Componentes Principales (Entidades y Relaciones)

■ Entidad (Rectángulo)

Función:
Representa un objeto, persona, lugar o concepto del mundo real sobre el cual se desea almacenar información en la base de datos. Existe de forma independiente.

Alumno
Ejemplo práctico: En el sistema de una universidad, Alumno, Profesor y Curso son Entidades.
⧈ Entidad Débil (Doble Rectángulo)

Función:
Es una entidad cuya existencia depende por completo de la presencia de otra entidad (llamada entidad fuerte o principal). No tiene una clave primaria propia que la identifique de forma única.

Dependiente
Ejemplo práctico: La entidad Dependiente (hijo de un empleado). Si el Empleado es borrado de la base de datos, sus dependientes ya no tienen razón de existir en el sistema.
◆ Relación (Rombo)

Función:
Representa la asociación, vínculo o interacción que existe entre dos o más entidades.

Alumno
Inscribe
Curso
Ejemplo práctico: La entidad Alumno se Inscribe en la entidad Curso. "Inscribe" es la relación.

2. Tipos de Atributos (Óvalos / Elipses)

● Atributo (Óvalo)

Función:
Define las propiedades, características o cualidades que describen a una entidad.

Alumno
Nombre
Ejemplo práctico: Para la entidad Alumno, sus atributos serían: Nombre, Edad y Correo electrónico.
⊚ Atributo Llave o Clave (Óvalo con texto subrayado)

Función:
Es el atributo principal que identifica de manera única e irrepetible a cada registro (instancia) dentro de una entidad.

Alumno
Matrícula
Ejemplo práctico: En la entidad Alumno, el atributo llave sería la Matrícula o ID_Alumno, ya que dos alumnos no pueden tener el mismo número.
◎ Atributo Multivaluado (Doble Óvalo)

Función:
Se utiliza para características que pueden tener más de un valor al mismo tiempo para un solo registro.

Empleado
Teléfono
Ejemplo práctico: El atributo Teléfono de un empleado, dado que una persona puede registrar un teléfono de casa, uno celular y uno de oficina.
🌿 Atributo Compuesto (Óvalo subdividido)

Función:
Es un atributo que se puede desglosar o dividir en varios sub-atributos más pequeños y específicos, los cuales tienen significado por sí mismos.

Dirección
Calle
Número
Ejemplo práctico: El atributo Dirección se compone de: Calle, Número, Colonia y Código Postal.
◌ Atributo Calculado / Derivado (Óvalo con línea punteada)

Función:
Representa un valor que no se almacena físicamente en la base de datos de forma estática, sino que se calcula dinámicamente a partir de otros datos existentes.

Alumno
Edad
Ejemplo práctico: El atributo Edad se calcula automáticamente restando la Fecha de Nacimiento de la fecha actual del sistema.

Tema 2: El Modelo de Base de Datos Relacional

¿Qué es el Modelo Relacional? Propuesto originalmente por Edgar F. Codd en 1970, es el modelo más utilizado hoy en día para administrar bases de datos. Su principio fundamental es organizar la información en tablas (o relaciones) compuestas por filas y columnas, permitiendo un acceso y manipulación de datos de manera intuitiva y matemática.

1. Características Clave del Modelo Relacional

  • Independencia Física y Lógica: La forma en que se almacenan los datos en el disco duro (física) no afecta a los programas ni a las consultas que los usuarios hacen (lógica).
  • Flexibilidad: Es muy fácil añadir nuevas columnas o tablas sin necesidad de reestructurar toda la base de datos desde cero.
  • Integridad de Datos: Reglas estrictas que garantizan que la información almacenada sea válida, coherente y que no existan datos "huérfanos".
  • Uso de Lenguaje Estándar: Utiliza principalmente SQL (Structured Query Language) para consultar, insertar, actualizar y borrar información.

2. Elementos Fundamentales de una Base de Datos Relacional

A. Relación (Tabla)

Es el elemento central. Una tabla representa una "entidad" del mundo real y contiene una colección de datos sobre un tema específico.

B. Tupla (Fila o Registro)

Corresponde a una fila horizontal en la tabla. Cada tupla representa un objeto o caso individual único dentro de esa tabla.

C. Atributo (Columna o Campo)

Es cada columna vertical de la tabla. Define una propiedad o característica específica que queremos guardar de cada registro.

D. Dominio

Es el conjunto de valores permitidos para un atributo determinado. Define el tipo de dato (ej. Entero, Texto, Fecha) y las restricciones (ej. que la edad sea un número entre 1 y 120).

4. Elementos de Vinculación y Control: Las Llaves (Keys)

1. Llave Primaria (Primary Key - PK)

Es un atributo (o combinación de ellos) que identifica de forma única e inequívoca a cada tupla en una tabla. No puede haber dos filas con la misma Llave Primaria, y este campo nunca puede quedar vacío (NOT NULL).

Ejemplo: En la tabla anterior, ID_Alumno es la Llave Primaria.

2. Llave Foránea o Ajena (Foreign Key - FK)

Es un atributo en una tabla cuyo valor debe coincidir exactamente con la Llave Primaria de otra tabla distinta. Es el mecanismo físico que crea la relación entre dos tablas.

Ejemplo: Si en la tabla de ALUMNOS añadimos una columna llamada ID_Carrera para conectarla con una tabla independiente de CARRERAS, esa columna actúa como Llave Foránea.
Regla de Oro (Integridad Referencial): Una Llave Foránea no puede contener un valor que no exista previamente como Llave Primaria en la tabla de origen. Esto evita que, por ejemplo, inscribamos a un alumno en una carrera que no existe en la institución.

Tema 3: El Modelo Entidad-Relación (MER) como Metodología

¿Qué es el Modelo Entidad-Relación? Es un modelo de datos de alto nivel que se emplea para diseñar la estructura conceptual de una base de datos. Sirve como un "puente" o plano arquitectónico que permite traducir los requerimientos del mundo real de una empresa hacia una estructura lógica que una computadora pueda entender (las tablas).

1. Características Principales del MER

  • Abstracción de Alto Nivel: No se preocupa por cómo se guardarán los archivos en el disco, ni por qué gestor de base de datos (MySQL, PostgreSQL, Oracle) se usará. Se enfoca puramente en la semántica de los datos.
  • Comprensión Universal: Al ser un modelo visual y semántico, funciona como una excelente herramienta de comunicación entre los ingenieros de sistemas y los clientes o usuarios finales.
  • Base para el Modelo Relacional: Existe una transición casi directa y matemática para convertir un Modelo Entidad-Relación en tablas relacionales.

2. Elementos Esenciales del Modelo

1. Entidades y Conjuntos de Entidades

A. Entidades Fuertes (o Regulares): Tienen existencia propia y poseen suficientes atributos para identificar de forma única cada uno de sus registros mediante una clave primaria.
Ejemplo: Un CLIENTE o un PRODUCTO.
B. Entidades Débiles: No pueden identificarse por sí mismas; dependen de una entidad fuerte para existir y su clave se compone de la combinación de la clave de la entidad fuerte más un discriminador propio.
Ejemplo: Las PARCIALIDADES de un pago. No existen pagos parciales si no se genera primero una FACTURA principal.

2. Atributos y sus Clasificaciones

A. Atributo Simple (Atómico): No se puede dividir en partes más pequeñas con significado propio.
Ejemplo: La Edad o el Precio de un artículo.
B. Atributo Compuesto: Se puede desglosar en componentes más pequeños que sí tienen significado independiente.
Ejemplo: El atributo NombreCompleto (dividido en Nombre, Apellido Paterno, Apellido Materno).
C. Atributo Monovalor: Tiene un único valor para una entidad en particular.
Ejemplo: El número de CURP de una persona (solo se tiene uno).
D. Atributo Multivalorado: Puede almacenar una colección o lista de valores para una misma celda o registro.
Ejemplo: Los CorreosElectrónicos de un cliente (puede tener dos o tres).
E. Atributo Derivado (o Calculado): Su valor se extrae o deduce a partir de otros atributos existentes mediante una operación.
Ejemplo: La Antigüedad de un empleado calculada con base en su Fecha de Contratación.

3. Relaciones y Grados de Relación

Relación Unaria (Recursiva): Una entidad se relaciona consigo misma.
Ejemplo: Un EMPLEADO supervisa a otros EMPLEADOS.
Relación Binaria (Grado 2): Participan exactamente dos entidades. Es el tipo más común en el diseño de bases de datos.
Ejemplo: Un CLIENTE realiza una COMPRA.
Relación Ternaria (Grado 3): Involucra de forma simultánea a tres entidades distintas en un solo evento.
Ejemplo: Un PROVEEDOR suministra un COMPONENTE a un PROYECTO específico.

3. Restricciones del Modelo: Mapeo y Participación

A. Razón de Mapeo (Cardinalidad)

  • Uno a Uno 1:1
  • Uno a Muchos 1:N
  • Muchos a Muchos N:M

B. Restricciones de Participación

  • Participación Total (Dependencia de existencia): Cada entidad en el conjunto debe participar obligatoriamente en al menos una relación del conjunto.
  • Participación Parcial: Algunas entidades del conjunto pueden o no participar en la relación.

Tema 4: Modelo Relacional y Proceso de Transformación (Mapeo)

¿Qué aprenderemos aquí? Diseñar un Diagrama Entidad-Relación (conceptual) es solo la mitad del trabajo. Para construir la base de datos real, debemos aplicar un conjunto de reglas matemáticas y lógicas para transformar esos diagramas en un Modelo Relacional (lógico) estándar, garantizando que no se pierda información ni consistencia en el proceso.

1. Características y Restricciones del Modelo Relacional

  • Atomicidad: Cada celda debe contener un único valor simple. No se permiten listas ni conjuntos de datos dentro de una celda.
  • Unicidad de Columnas: Cada columna en una tabla debe tener un nombre único.
  • Unicidad de Tuplas: No pueden existir dos filas exactamente idénticas en una misma tabla; de ahí la obligación de definir una Llave Primaria (PK).
  • El orden es irrelevante: El orden físico de las filas o de las columnas no altera el significado ni el comportamiento de los datos.

2. Procedimiento de Transformación (Mapeo de MER a Tablas)

Paso 1: Transformación de Entidades Fuertes

Cada entidad fuerte del diagrama se convierte directamente en una tabla independiente. Los atributos simples de la entidad se convierten en las columnas de la tabla, y el atributo llave se define como la Llave Primaria (PK).

Modelo Conceptual

Matricula
───
ALUMNO
───
Nombre
➔
Modelo Lógico Resultante
ALUMNO (Matricula, Nombre)
Ejemplo: La entidad ALUMNO con llave Matricula y atributo Nombre.
Paso 2: Transformación de Entidades Débiles

Cada entidad débil se convierte en una tabla. Sus columnas serán sus propios atributos más la **Llave Primaria de la entidad fuerte** de la que depende. Esta clave copiada actuará como Llave Foránea (FK), y la unión de ambas claves formará la Llave Primaria compuesta de la nueva tabla.

Modelo Conceptual

EMPLEADO
===
DEPENDIENTE
➔
Modelo Lógico Resultante
DEPENDIENTE (ID_Empleado (FK), NombreHijo, Parentesco)
Ejemplo: La entidad débil DEPENDIENTE (hijo de un empleado) depende de EMPLEADO.
Paso 3: Transformación de Relaciones 1:N (Uno a Muchos)

En este tipo de relación no se crea una tabla nueva. En su lugar, la Llave Primaria de la entidad del lado "Uno" se copia y se pega dentro de la tabla del lado "Muchos" (N) en forma de Llave Foránea (FK). Si la relación tenía atributos propios, estos también se mudan al lado "Muchos".

DEPARTAMENTO
── 1 ── ‹R› ── N ──
EMPLEADO
➔
Modelo Lógico Resultante
EMPLEADO (ID_Empleado, Nombre, ID_Depto (FK))
Ejemplo: Un DEPARTAMENTO (1) tiene muchos EMPLEADOS (N). La clave ID_Depto viaja a la tabla de empleados.
Paso 4: Transformación de Relaciones N:M (Muchos a Muchos)

Toda relación Muchos a Muchos se transforma obligatoriamente en una nueva tabla independiente (a menudo llamada tabla intermedia o asociativa). Su Llave Primaria será compuesta, formada por la combinación de las Llaves Primarias de las dos entidades participantes. Si la relación tenía atributos propios, se añaden a esta nueva tabla.

MATERIA
➔
Modelo Lógico (¡Nace tabla intermedia!)
INSCRIPCION (Matricula (FK), ID_Materia (FK), CalificacionFinal)
Ejemplo: Muchos ALUMNOS (N) cursan muchas MATERIAS (M). Se genera la tabla intermedia INSCRIPCION.
Paso 5: Tratamiento de Atributos Multivalorados

Como el modelo relacional prohíbe guardar listas de datos en una sola celda (regla de atomicidad), cada atributo multivalorado se convierte en una tabla independiente. Esta tabla contendrá el atributo en sí y la Llave Primaria de la entidad original para poder saber a quién le pertenece ese dato.

Ejemplo: Si la entidad EMPLEADO tiene el atributo multivalorado Telefono.

3. Resumen de Reglas de Relación (Mapeo Rápido)

Para que los alumnos lo recuerden de forma mnemotécnica antes de un examen o proyecto:

  • Relación 1 : 1 → La clave de una entidad pasa a la otra como FK (preferentemente a la que tenga participación total).
  • Relación 1 : N → La clave del "1" viaja al "N" como FK. ("El fuerte adopta al débil").
  • Relación N : M → ¡Alerta! El rombo se destruye y nace una nueva tabla intermedia con claves combinadas.
