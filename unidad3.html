UNIDAD III.1 Gestores de Base de Datos Relacionales
Sistemas Manejadores

1. Concepto y Características de un RDBMS

Un Sistema Manejador de Bases de Datos Relacionales (RDBMS) es el software que permite crear, actualizar, administrar y consultar una base de datos relacional basada en el álgebra y el modelo formal de Edgar F. Codd.

Estructura Relacional: Organiza la información exclusivamente en forma de tablas bidimensionales (relaciones) compuestas por filas (tuplas) y columnas (atributos).
Lenguaje Estándar: Implementa de manera nativa SQL (Structured Query Language) para todas las operaciones de definición, manipulación y control de accesos.
Consistencia Transaccional: Sigue estrictamente las propiedades ACID (Atomicidad, Consistencia, Aislamiento y Durabilidad) para blindar los datos operativos de fallos lógicos o físicos del sistema.
Esquema 1: Capa de abstracción transaccional en un RDBMS.
Nota de arquitectura: La principal diferencia entre un DBMS tradicional de archivos jerárquicos y un RDBMS moderno radica en que este último obliga formalmente al motor a validar restricciones lógicas de claves foráneas e integridad referencial en tiempo real.
Sistemas de Tipificación

2. Tipos de Datos en el Motor Relacional

Clasificación estándar de las estructuras de almacenamiento nativas que definen el dominio de valores permitidos y las operaciones válidas por columna:

  • Numéricos Exactos y Aproximados: Uso de INT o BIGINT para identificadores atómicos, y DECIMAL(P,S) (punto fijo) para evitar pérdidas de precisión centesimal en cálculos financieros, a diferencia de los tipos aproximados FLOAT o DOUBLE.
  • Cadenas Alfanuméricas: Contraste crítico entre CHAR (longitud estática óptima para hashes y códigos ISO fijos) y VARCHAR (longitud variable dinámica con byte de control).
  • Cronológicos Estrictos: Modelado preciso con DATE, DATETIME y TIMESTAMP; este último ligado automáticamente al huso horario del sistema para auditorías eficientes de registros.
  • Objetos Binarios (BLOB): Contenedores dedicados para el resguardo de bytes puros sin procesar, tales como documentos adjuntos, imágenes codificadas o recursos cifrados.
Anatomía Interna

3. Componentes y Funciones del RDBMS

Análisis de los módulos lógicos internos de un motor relacional y el rol crítico que cumple cada sección en la pila transaccional:

Componente Core Función Técnica Principal
Motor de Almacenamiento (Storage Engine) Mapea y escribe las filas lógicas de SQL en bloques binarios persistentes en el disco duro o memoria RAM.
Optimizador de Consultas (Query Optimizer) Analiza los índices disponibles y calcula el camino algebraico más eficiente y rápido para resolver un Query.
Procesador DDL / DML Compila y ejecuta las sentencias imperativas del usuario en instrucciones de bajo nivel legibles por el sistema operativo.
Gestor de Transacciones y Logs Monitorea las operaciones concurrentes y gestiona las bitácoras de recuperación inmediata ante fallos eléctricos (Write-Ahead Logging).
Gobierno de Datos

4. Procedimiento de Selección Corporativa

Metodología técnico-institucional para elegir el motor de base de datos relacional óptimo acorde al perfil de requerimientos de la organización:

1. Análisis de Concurrencia y Carga: Dimensionar el volumen proyectado de lecturas y escrituras simultáneas por segundo (TPS) para evaluar si el motor soporta escalamiento vertical o replicación horizontal.
2. Costo Total de Propiedad (TCO): Evaluar los costos de licenciamiento comercial corporativo (ej. Oracle, SQL Server) frente al costo operativo y de infraestructura de soluciones robustas de código abierto (ej. PostgreSQL, MySQL).
3. Ecosistema, Soporte y Seguridad: Validar el nivel de blindaje criptográfico nativo, cumplimiento de normativas globales de protección de datos (GDPR/ISO) y la disponibilidad de herramientas de diagnóstico.
Regla de oro: No existe un RDBMS perfecto, sino el adecuado. Para proyectos corporativos complejos con alta carga de triggers y funciones analíticas, PostgreSQL es el estándar open-source; para soluciones web ligeras y de alta velocidad de lectura, MySQL/MariaDB domina el sector.
UNIDAD III.2 Gestores de Bases de Datos No Relacionales (NoSQL)
Sistemas de Tipificación

1. Tipos de Datos y Estructuras NoSQL

A diferencia de las tablas rígidas, los motores NoSQL manejan esquemas flexibles y dinámicos:

  • Documentos BSON/JSON: Almacenan pares clave-valor anidados, arreglos internos y objetos complejos independientes de un esquema fijo.
  • Estructuras de Clave-Valor pura: Almacenamiento directo en caché donde el valor es un bloque de bytes opaco indexado por un identificador único.
  • Grafos (Nodos/Aristas): Representaciones de entidades conectadas directamente sin uniones complejas, ideales para redes sociales y motores de recomendación.
Arquitectura Core

2. Componentes y Funciones de Motores NoSQL

Módulos especializados para procesar volúmenes masivos de datos distribuidos en clústeres:

Mecanismo de Sharding: Fragmenta y distribuye colecciones de datos horizontalmente a lo largo de múltiples servidores físicos automáticos.
Motor de Replicación: Duplica conjuntos de datos entre nodos primarios y secundarios para asegurar alta disponibilidad y tolerancia a fallos de hardware.
Teorema CAP: Diseñados priorizando la Disponibilidad (Availability) y Tolerancia al Particionado (Partition tolerance) sacrificando la consistencia inmediata (Consistencia Eventual).

UNIDAD III.3 Normalización de Bases de Datos
Fundamentos Teóricos

1. El Concepto de Dependencia Funcional

Es una restricción matemática entre dos atributos de una relación. Se dice que un atributo Y depende funcionalmente de un atributo X (X ➔ Y) si y solo si, cada valor de X tiene asociado exactamente un único valor de Y.

CURP (X)
➔
Nombre Completo (Y)
Esquema 2: Mapeo inequívoco de una determinante funcional (X determina a Y).
Ejemplo: El número de RFC o CURP determina funcionalmente el Nombre de un cliente en un sistema. Si conoces el CURP, no puede haber dos nombres distintos asociados.
Reglas del Diseño

2. Las Formas Normales (1FN, 2FN, 3FN)

Proceso progresivo para eliminar la redundancia de información y prevenir anomalías de inserción, actualización y borrado:

  • Primera Forma Normal (1FN): Exige la atomicidad de los datos. Prohíbe terminantemente grupos repetitivos y campos con múltiples valores separados por comas.
  • Segunda Forma Normal (2FN): Debe estar en 1FN y asegurar que todo atributo no clave dependa de forma completa de la clave primaria, eliminando dependencias parciales.
  • Tercera Forma Normal (3FN): Debe estar en 2FN y garantizar que no existan dependencias transitivas (atributos que dependan de otros atributos que no forman parte de la clave primaria).

UNIDAD III.4 Lenguaje SQL: Definición de Datos (DDL)
Lenguaje Estándar

1. El Rol de las Sentencias DDL

El Data Definition Language (DDL) es el subconjunto de SQL especializado en crear, alterar y destruir las estructuras lógicas del motor de base de datos, modificando de forma directa el diccionario de datos del sistema.

A diferencia de DML (SELECT, INSERT), las operaciones DDL son estructurales y, en la mayoría de los motores de bases de datos relacionales, ejecutan un Auto-Commit implícito irrevocable.
Sintaxis de Instrucción

2. Estructuras Fundamentales de Sintaxis

Las tres operaciones columnas que rigen el ciclo de vida de los objetos en un RDBMS:

  • CREATE TABLE alumnos (...);
    Instancia una nueva estructura definiendo nombres de columna, tipos de datos y restricciones de integridad primarias/foráneas.
  • ALTER TABLE alumnos ADD COLUMN telefono VARCHAR(15);
    Modifica la estructura de una entidad existente sin corromper ni eliminar los registros previamente almacenados.
  • DROP TABLE alumnos;
    Remueve permanentemente tanto la estructura como la totalidad de los datos de la tabla del disco físico.
CREATE TABLE alumnos (
  id_alumno INT PRIMARY KEY,
  nombre VARCHAR(50)
);

UNIDAD III.5 Construcción Lógica a Física
Ingeniería de Datos

Procedimiento de Transformación de Modelos

El paso definitivo para materializar las abstracciones analíticas en un entorno de producción operativo controlado sigue este flujo metodológico estricto:

  1. Mapeo de Entidades a Tablas Físicas: Cada entidad identificada en el Modelo Entidad-Relación o lógico se convierte en una tabla independiente dentro del esquema del motor de destino.
  2. Conversión de Atributos a Columnas Tipificadas: Se asigna un tipo de dato binario físico optimizado para cada atributo del diseño lógico (por ejemplo, transformar un texto genérico de descripción en un campo estructurado VARCHAR(250) o TEXT).
  3. Implementación de Claves Primarias y Foráneas: Declaración explícita de restricciones (Constraints) PRIMARY KEY y FOREIGN KEY para garantizar que el motor realice la validación automática de la integridad referencial.
  4. Generación de Índices Físicos y Optimización: Creación dirigida de estructuras de indexación B-Tree o Hash en aquellas columnas identificadas críticamente como de alta consulta para maximizar el rendimiento transaccional.
