Configuración General

1. Configuración General de la Tabla

Propiedades globales de la entidad física dentro del motor relacional:

Table Name: Es el nombre identificador de la entidad, en este caso Cliente.
Database: Indica el esquema al que pertenece, llamado mitiendota.
Engine: Configurado como InnoDB, ideal para llaves foráneas e integridad transaccional.
Character Set: Configurado en [default] para heredar el juego de caracteres base (UTF-8).
Collation: Configurado en [default], heredando reglas nativas de ordenamiento.
Diseño Atómico

2. Estructura de id_cliente

Análisis y definición de atributos primarios del primer campo de la tabla:

Column Name: El nombre técnico del campo es id_cliente.
Data Type: El tipo de dato asignado corresponde a int (entero).
Length: No definido explícitamente (asume 11 por defecto), regula el límite de visualización.
Default: Vacío; sin asignación de valor predeterminado manual.
Restricciones Físicas

3. Restricciones y Atributos (Checkboxes)

Configuración lógica de integridad estructural para la entidad cliente:

  • PK? (Primary Key): Desmarcado. Debería activarse para asegurar unicidad.
  • Not Null?: Desmarcado. Permitiría la inserción de nulos erróneos.
  • Unsigned?: Desmarcado. Evita enteros negativos optimizando el rango de IDs.
  • Auto Incr?: Desmarcado. Recomendado delegar el autoincremento al DBMS.
  • Zerofill?: Desmarcado. Completaría con ceros lógicos a la izquierda.
  • On Update: Sin acción temporal configurada de forma nativa.
  • Comment: Metadato documental descriptivo para ingenieros de desarrollo.
Observación de experto: Para que esta tabla sea funcional, el alumno debe marcar las casillas de PK, Not Null y Auto Incr en la fila de id_cliente. Sin esto, la tabla no tendrá una forma de identificar de manera única a cada cliente.
Campos Calculados

4. Virtualidad y Lógica Calculada

Gestión y comportamiento dinámico de campos derivados en memoria:

Virtuality: Blanco. Permite discriminar si la columna es física, virtual o almacenada persistente.
Expression: Sentencia para fórmulas lógicas. Al ser id_cliente un dato atómico base, permanece vacío.
UNIDAD II.5 Diccionario de Tipos de Datos
Álgebra Numérica

5. Tipos de Datos Numéricos

Clasificación precisa de almacenamiento numérico según precisión y rango:

  • tinyint: Entero muy pequeño. Rango de -128 a 127 (o 0 a 255 Unsigned).
  • smallint: Entero pequeño. Rango de -32,768 a 32,767.
  • mediumint: Entero medio. Rango de -8,388,608 a 8,388,607.
  • int: El estándar para números enteros (como el id_cliente).
  • bigint: Entero masivo para entornos transaccionales de alta escala.
  • decimal / Numeric: Punto fijo para transacciones financieras exactas.
  • float: Punto flotante de precisión simple. Menor peso en bytes.
  • double / real: Punto flotante de precisión doble para cálculo científico.
  • bit: Banderas lógicas binarias (valores discretos 0 y 1).
  • bool / boolean: Sinónimo directo de Tinyint(1). Cero es False.
Cadenas de Bloque

6. Tipos de Datos de Cadena (Texto)

Estructuras para el resguardo de información alfanumérica:

  • char: Longitud fija con relleno sintáctico automático de espacios.
  • varchar: Longitud variable optimizada más byte de control de longitud.
  • tinytext: Texto corto aislado con un límite de 255 caracteres.
  • text: Bloques estándar para resguardar descripciones de negocio.
  • mediumtext: Diseñado para cuerpos robustos como posts de blogs.
  • longtext: Almacenamiento masivo de logs complejos o archivos planos.
  • enum: Dominios cerrados con selección unitaria explícita.
  • set: Dominio de selección múltiple sobre lista predefinida.
Líneas de Tiempo

7. Tipos de Datos de Fecha y Tiempo

Estructuras nativas para el control cronológico y auditorías:

  • date: Resguardo exclusivo cronológico bajo formato AAAA-MM-DD.
  • time: Control temporal aislado en formato estricto HH:MM:SS.
  • datetime: Estructura unificada estática de fecha y hora.
  • timestamp: Sello dinámico acoplado a la zona horaria del servidor.
  • year: Representación discreta anual en formatos de 2 o 4 dígitos.
Objetos Binarios

8. Tipos Binarios y Archivos

Tipificación especializada para objetos complejos sin serializar:

  • binary: Cadenas binarias estáticas de longitud fija rígida.
  • varbinary: Estructuras de almacenamiento binario dinámico adaptable.
  • blob: Binary Large Object dedicado a iconos y recursos livianos.
  • tinyblob: Variación de baja escala del contenedor binario Blob.
  • mediumblob: Idóneo para imágenes de perfil de usuarios y multimedia media.
  • longblob: Contenedor absoluto para PDFs pesados o secuencias de video.
UNIDAD II.5 Motores de Almacenamiento e Integridad Internacional
Sistemas de Archivo

9. Motores de Almacenamiento (Engine)

Componentes core encargados de mapear las operaciones del procesador SQL en el almacenamiento físico persistente:

1. InnoDB: Estándar industrial transaccional robusto. Garantiza cumplimiento estricto de ACID, bloqueo nativo a nivel de fila y aislamiento avanzado para mitigar condiciones de carrera concurrentes.
2. MyISAM: Arquitectura clásica no transaccional. Carece de claves foráneas, bloquea tablas completas en escritura, pero mantiene velocidades altas en arquitecturas dedicadas 100% a consultas de lectura.
3. Aria: Evolución nativa de MyISAM dentro del ecosistema MariaDB. Preserva la velocidad e introduce tolerancia a fallas críticas del sistema.
4. MEMORY: Mapeo directo sobre memoria RAM voltátil. Velocidad pura idónea para tablas temporales o capas internas de caché. Los datos se destruyen al reiniciar el proceso.
5. CSV: Formateo plano estructurado en texto delimitado por comas, facilitando integraciones nativas e intercambios sin parsers con suites ofimáticas.
6. SEQUENCE: Motor virtual especializado en generar sucesiones aritméticas dinámicas en memoria sin generar costo de almacenamiento en disco.

Encoding Avanzado

11. Diferencia: utf8 vs utf8mb4

Manejo óptimo del esquema de codificación multibyte dentro del servidor de datos:

  • utf8 (utf8mb3): Limitado a representaciones de máximo 3 bytes. Excluye glifos modernos de la especificación global.
  • utf8mb4: Implementación absoluta de UTF-8 de hasta 4 bytes por carácter. Soporta emojis (😂, 🚀), juegos de caracteres complejos orientales y sintaxis algebraica avanzada.
Cotejamiento Semántico

12. Cotejamientos y Reglas de Sufijos

Configuraciones de ordenamiento filológico y semántica de comparación de cadenas:

CollationPropiedad TécnicaUso recomendado
utf8mb4_unicode_ciPrecisión multiidioma completa. Diferencia caracteres especiales.Estándar internacional.
utf8mb4_general_ciRendimiento rápido mediante atajos en algoritmos de comparación.Entornos de alta demanda de CPU.
utf8mb4_spanish_ciReglas heredadas del español (ch, ll).Proyectos locales específicos.

Significado analítico de sufijos estructurales:

  • _ci (Case Insensitive): Ignora diferencias explícitas entre mayúsculas y minúsculas (A = a). Ideal para control de accesos.
  • _bin (Binary): Evaluación estricta por el peso posicional binario de cada carácter. (A ≠ a).
  • _ai (Accent Insensitive): Neutralidad ante tildes y diacríticos. (música = musica).
Dato curioso: utf8mb4_unicode_ci es el "todoterreno" que hará que tus búsquedas y ordenamientos funcionen como un usuario normal espera.
