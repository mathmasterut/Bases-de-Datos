Tema 5: El Diccionario de Datos

Concepto, características y documentación de metadatos

¿Qué es un Diccionario de Datos? En términos sencillos, es un listado organizado y detallado que contiene la descripción técnica de todos los elementos que componen una base de datos. No almacena los datos reales de los clientes o alumnos, sino que almacena "datos sobre los datos" (Metadatos), sirviendo como la guía de referencia oficial para los desarrolladores y administradores del sistema (DBA).

1. Características de un Diccionario de Datos

Un buen diccionario de datos debe cumplir con características esenciales para garantizar su utilidad en un proyecto de software:

  • Precisión y Consistencia: Define un único nombre y tipo de dato para cada elemento en todo el sistema, evitando que dos desarrolladores llamen al mismo dato de formas diferentes (ej. evitar usar tel_cli en una pantalla y celular en otra).
  • Centralización: Funciona como el punto único de verdad. Cualquier duda sobre la longitud, restricciones o propósito de un campo se resuelve consultando este documento.
  • Soporte para el Mantenimiento: Si en el futuro se necesita cambiar la longitud de un campo (por ejemplo, expandir el código postal para soporte internacional), el diccionario permite evaluar rápidamente a qué tablas afectará el cambio.
  • Integración con el SGBD: La mayoría de los Sistemas Gestores de Bases de Datos modernos generan y mantienen un diccionario de datos interno de forma automática (a menudo llamado catálogo del sistema), el cual consultan antes de ejecutar cualquier consulta SQL para validar si las tablas y columnas existen.

2. Elementos Principales que se Documentan

Para cada campo o columna de una tabla, el diccionario de datos suele registrar la siguiente información obligatoria:

  • Nombre del Campo: El identificador técnico exacto que se usa en el código SQL (ej. id_alumno).
  • Alias (opcional): Nombre alternativo o comercial con el que los usuarios finales conocen el dato (ej. "Número de Matrícula").
  • Tipo de Dato y Longitud: Especifica si es texto, entero, decimal, fecha, etc., junto con su tamaño máximo (ej. VARCHAR(50)).
  • Tipo de Llave: Indica si el campo es una Llave Primaria (PK), Llave Foránea (FK) o un campo común.
  • Restricciones (Constraints): Reglas que el campo debe cumplir obligatoriamente (ej. si acepta valores nulos NULL / NOT NULL, si es un valor único UNIQUE, o rangos permitidos).
  • Descripción: Una breve explicación textual sobre el propósito de ese campo dentro del negocio.

3. Ejemplo Gráfico: Estructura de un Diccionario de Datos

A continuación se muestra cómo se documenta formalmente una tabla dentro del diccionario de datos. Este es el formato estándar que los alumnos deben replicar en sus proyectos escolares:

Nombre de la Tabla: ALUMNOS
Descripción: Almacena la información de los estudiantes inscritos en la institución.
Nombre del Campo Tipo de Dato Llave Acepta Nulos Valor por Defecto Descripción / Reglas de Negocio
id_alumno INT PK NO (NOT NULL) Autoincrementable Identificador único asignado a cada estudiante al ingresar.
nombre VARCHAR(60) -- NO (NOT NULL) Ninguno Nombre(s) y apellidos completos del alumno.
correo_inst VARCHAR(50) -- SÍ Ninguno Correo electrónico institucional. Debe ser único (UNIQUE).
fecha_ingreso DATE -- NO (NOT NULL) CURRENT_DATE Fecha exacta en la que el alumno se dio de alta en el sistema.
id_carrera INT FK NO (NOT NULL) Ninguno Se conecta con la tabla de CARRERAS para validar la especialidad.

4. Resumen Analógico para el Alumno

Piénsalo de esta manera: Si una Base de Datos fuera una casa inteligente recién construida, los datos reales serían los muebles y las personas que viven dentro. El Diccionario de Datos sería el plano arquitectónico y el manual técnico de la instalación eléctrica: te dice exactamente de qué tamaño es cada tubería, dónde se conecta cada cable y qué voltaje soporta, asegurando que si algo se descompone o cambia, sepas exactamente dónde intervenir sin tirar una pared.
